# Assessment success criteria

This is the canonical coverage checklist derived from the [candidate brief](task-brief.md). The brief governs requirements; project-added checks are labeled separately below. Coverage is independent of decision approval, task status, AI-log review, and commit status.

**Status:** Not started = no implementation evidence; Partial = some evidence but requirements or checks remain; Verified = evidence demonstrates the complete criterion; Gap = a known failure or unmet submission requirement. **Last full assessment verification:** not yet performed. The baseline below is a manual documentation/code inspection on 2026-11-08, informed by the historical [AI log](AI_LOG.md). Historical automated runs and live-model observations are labeled explicitly; none verifies the complete product.

The [v2 roadmap](roadmap.md) assigns live CLI provider integration and revised CLI behavior to Phase 02, and independent model evaluation to Phase 03, SQLite and HTTP verification to Phase 04, and identity cases to Phase 05. Existing evidence below describes the historical implementation. The revised [classification policy](processing-resolution-policy.md) adds mixed intent to the brief's minimum contract.

## Delivery constraints

The brief targets approximately five focused hours, a three-day submission window, and a 60-minute live extension session. No exact elapsed effort or deadline has been established here. If time runs out, document unfinished work honestly.

## Review cadence

Before each phase, link the criteria it advances and define observable task and exit checks. After verification, update affected coverage with dated evidence and identify regressions or incomplete checks. At phase close-out, review the criteria and carry remaining work into the [roadmap](roadmap.md). At plan finalization and submission, review the entire checklist, including decision rationale, original-plan provenance, agent errors and session evidence. Do not mark a criterion Verified solely because a plan or mock exists.
